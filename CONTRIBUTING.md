# Mitwirken

Vielen Dank für das Interesse am seifert-it Security Reader.

## Fehler melden

Bitte vor einem neuen Issue prüfen, ob der Fehler bereits gemeldet wurde. Eine hilfreiche Meldung enthält:

- verwendete macOS-Version
- Reader-Version
- erwartetes und tatsächliches Verhalten
- nachvollziehbare Schritte
- betroffene Feed-Adresse, sofern relevant
- Bildschirmfoto oder Fehlermeldung ohne persönliche Daten

Sicherheitslücken bitte nicht öffentlich melden. Dafür gilt [SECURITY.md](SECURITY.md).

## Änderungen einreichen

1. Einen eigenen Branch anlegen.
2. Änderungen klein und thematisch eindeutig halten.
3. Bestehendes Verhalten durch Tests absichern.
4. `swift test` lokal ausführen.
5. Pull Request mit Motivation, Umfang und Prüfschritten erstellen.

## Stil

- Swift-API-Design-Guidelines befolgen.
- Bezeichner sollen Absicht und Fachbedeutung ausdrücken.
- UI- und Datenlogik getrennt halten.
- Kommentare nur ergänzen, wenn der Grund einer Entscheidung nicht aus dem Code hervorgeht.
- Keine Zugangsdaten, personenbezogenen Daten oder lokalen Bibliotheksdateien einchecken.

Mit einem Beitrag wird bestätigt, dass der eingereichte Code selbst erstellt wurde oder rechtmäßig beigetragen werden darf. Eine spätere Projektlizenz gilt nur, wenn sie ausdrücklich im Repository veröffentlicht wurde.
